## Browser Operator goal
- บอสยืนยันว่าต้องการให้สลี่ทำงานบน Google Chrome ที่บอสเห็นได้แบบ Manus Browser Operator: เปิดเว็บ กรอกฟอร์ม และดำเนินงานหลายขั้นตอน ขณะที่บอสมองดูได้; ต้องมี browser bridge/extension เชื่อม Chrome จริงก่อน และเมื่อเจอ login/password/OTP/CAPTCHA หรือการยืนยันสำคัญ ให้บอสรับช่วงเอง จากนั้นสลี่ทำต่อ
- ผลค้น Manus เอกสารทางการแยก Cloud Browser (คลาวด์) ออกจาก Browser Operator (เบราว์เซอร์ local); สรุปบันทึกไว้ใน knowledge/analysis/manus-visible-browser-agent.md
- ขณะนี้แชตนี้ยังไม่มีช่องทางควบคุม Chrome ของบอสโดยตรง; อย่าทำเหมือนต้นแบบ DeskOS หรือส่ง URL localhost เท่ากับทำได้
- ทดลองตรวจช่องทางจริง: Browser MCP ที่มีใน workspace ใช้ Playwright chromium.launch() สร้าง browser session แยก (headless โดยค่าเริ่มต้น) ไม่ใช่ Chrome ที่ผู้ใช้เปิด; ports CDP 9222/9223/9224 ไม่ตอบ และ Browser tool ของแชตแจ้งไม่พร้อม แนะนำ `cow install-browser` แต่สลี่ไม่ได้รันโดยไม่มีการยืนยันจากบอส เพราะอาจติดตั้ง/เปลี่ยน environment; ขั้นต่อไปต้องเตรียม browser integration ที่ต่อ Chrome จริง ไม่ใช่ใช้ isolated browser
- บอสแจ้งว่า `cow install-browser` ติดตั้งใน Termux ไม่ได้ จึงลองทาง Android intent โดยไม่ติดตั้งเพิ่ม: `am start -a android.intent.action.VIEW -d https://example.com -p com.android.chrome` สำเร็จในความหมายว่า Android รับคำสั่งเปิด Chrome; แต่ Termux ตรวจไม่พบ Chrome CDP endpoint (9222/9223) หรือ devtools socket ดังนั้นเปิดหน้าได้ แต่ควบคุมคลิก/พิมพ์ใน Chrome จริงยังไม่ได้
