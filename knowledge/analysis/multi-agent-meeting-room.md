# ห้องประชุมหลาย Agent ใน NovaAgent

> Source: การตรวจโค้ด NovaAgent-Clean และการตัดสินใจร่วมกับบอส วันที่ 2026-10-22

## สรุป
NovaAgent มีโครงสร้างห้องประชุมหลาย Agent อยู่แล้ว จึงไม่ควรสร้างระบบใหม่หรือเพิ่มไฟล์ขนาดใหญ่โดยไม่จำเป็น

## พฤติกรรมที่ยืนยันจากโค้ด
- UI เลือก Agent ได้อย่างน้อย 2 ตัว
- Agent ตัวแรกเป็นเจ้าของ/ตัวหลักของ session
- Agent ที่เหลือถูกบันทึกเป็น `members` ของ session
- backend มี endpoint ตั้งค่า session และรองรับ `members` เป็นรายการ Agent IDs
- ระบบสร้าง roster จากเจ้าของและสมาชิก เพื่อให้บทสนทนาร่วมกันอ้างถึง Agent อื่นได้
- UI โหลดสถานะทีมจาก session settings และแสดงสมาชิกใน composer
- ห้องกลุ่มไม่ใช้ model pin เดียว เพราะแต่ละ Agent ใช้การตั้งค่าของตัวเอง
- เปลี่ยนสมาชิกของ session ได้โดยไม่ต้องสร้างระบบใหม่หรือรีสตาร์ตทั้งบริการ

## วิธีใช้งานที่คาดหวัง
1. กดสร้างแชทใหม่
2. เลือกแชทกลุ่ม / ห้องประชุม
3. เลือก Agent อย่างน้อย 2 ตัว
4. ตัวแรกทำหน้าที่เป็น Agent หลัก
5. เริ่มส่งข้อความ แล้วเรียก Agent สมาชิกผ่านบริบทของห้อง

## ข้อจำกัดที่ควรคุม
- จำกัดจำนวน Agent และรอบการตอบเพื่อป้องกันค่าใช้จ่ายและการวนลูป
- ไม่ส่ง credential หรือ secret เข้า shared context
- ทดสอบ behavior ผ่าน public session/settings seam ก่อนแก้โค้ด
- ไม่สร้าง artifact ใหญ่ หากยังไม่มีประโยชน์ชัดเจน
