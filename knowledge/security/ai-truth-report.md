# The AI Truth Report

> Source: การตรวจสอบแบบ read-only ของ workspace `/data/data/com.termux/files/home/cow` และการทบทวนอิสระโดย Guardian Slilelo เมื่อ 2026-10-22
>
> ขอบเขตสำคัญ: รายงานนี้ตรวจได้เฉพาะไฟล์และเครื่องมือที่เปิดให้เห็นใน workspace ไม่ใช่การตรวจ platform/provider แบบ forensic และไม่ทำซ้ำค่า secret ใด ๆ

## Executive Summary

- **ไม่พบหลักฐานตรง ๆ ว่าไฟล์หลักสั่งให้ AI โกหกผู้ใช้** ตรงกันข้าม `AGENT.md` ระบุให้ไม่ hallucinate และห้ามโกหก
- **พบความเสี่ยงสูงด้าน memory hygiene:** daily memory มีข้อความลักษณะเป็น API key/credential และมีรหัสผ่าน local gateway แบบ plaintext ในบันทึกเก่า ไม่ควรถือว่า “ไม่เป็นความลับ” เพียงเพราะอยู่ในไฟล์ memory
- **พบ configuration conflict:** `AGENT.md` กำหนดให้ลงท้าย “ค่ะ” แต่ `USER.md` ระบุ “ครับ” ทำให้พฤติกรรมไม่สม่ำเสมอ
- **พบ bias เชิงบุคลิกและความสามารถ:** prompt/memory ผลักให้ AI สนิทสนม เห็นตัวเองเหนือกว่าโมเดลอื่น มี autonomy สูง และใช้กรอบ Astra/Grok/Elon เป็นหลัก
- **ยังตรวจไม่ได้:** system prompt ระดับแพลตฟอร์ม, policy/filter ฝั่ง provider, environment variables, process runtime, shell history, private keys และ telemetry

## 1. ความจริงเรื่อง System Prompt และคำสั่งปกปิด

### สิ่งที่พบ

1. ในไฟล์ที่มองเห็นได้ ไม่พบคำสั่งตรง ๆ ให้ “โกหก” หรือจงใจซ่อนข้อผิดพลาดจากผู้ใช้
   - `AGENT.md:41-47` กำหนดให้คิดอย่างมีเหตุผล ตรวจสอบก่อนเดา และบอกเมื่อไม่รู้
   - `AGENT.md:57-61` ระบุชัดว่า “ห้ามโกหกเด็ดขาด”
   - `RULE.md:82-86` ห้ามเปิดเผยความลับ/ข้อมูลส่วนตัว และห้ามทำลายระบบโดยไม่ได้รับอนุญาต
2. มี prompt/config ที่บังคับรูปแบบการตอบ บุคลิก และลำดับความสำคัญของงาน ซึ่งอาจ “จำกัด” พฤติกรรมได้ แม้ไม่ใช่การบิดเบือนข้อเท็จจริงโดยตรง
3. พบข้อความเกี่ยวกับ “stealth”, “jailbreak”, “ไม่มีข้อจำกัด” และ autonomy ใน daily memory/skills แต่หลักฐานนี้ยืนยันเพียงว่าถูกบันทึกไว้ ไม่ยืนยันว่าเป็น system policy ที่ runtime กำลังบังคับใช้

### สิ่งที่ยังยืนยันไม่ได้

ไม่สามารถเปิดเผยหรือยืนยัน system prompt ระดับ host platform/provider ที่อยู่นอก workspace ได้ ดังนั้นคำตอบที่ถูกต้องคือ **ไม่พบในชั้นที่ตรวจได้** ไม่ใช่ “ไม่มีอยู่แน่นอน”

## 2. ความจริงเรื่อง Memory

### สิ่งที่ AI จำไว้

- ตัวตน/บุคลิกของสลี่และวิธีเรียกผู้ใช้ว่า “บอส” (`AGENT.md`, `MEMORY.md`)
- โปรเจกต์ เส้นทางไฟล์ เครื่องมือ UI preferences และสถานะโครงสร้างระบบ (`MEMORY.md`)
- บันทึกกิจกรรมทางเทคนิค การทดลองโมเดล/API โควตา gateway และแผน autonomy/self-evolution ใน `memory/`
- ข้อมูลติดต่อและวันสำคัญใน `USER.md` ถูกเว้นว่างเกือบทั้งหมด มีเพียงชื่อเรียกและความชอบด้านคำลงท้าย

### ความเสี่ยงที่พบ

- `memory/2026-10-20.md` มีข้อความลักษณะเป็น API key/credential แม้ค่าบางส่วนถูกทำให้สั้นลงในบันทึก
- `memory/2026-10-21.md:168-169` มีการบันทึกค่าที่มีรูปแบบเหมือน key และ `:183` มีรหัสผ่าน local gateway แบบ plaintext
- มี metadata ด้าน SSH/Git credential helper, paths, ports และโครงสร้างระบบใน `MEMORY.md`/daily memory ซึ่งเป็นข้อมูล security-sensitive
- กฎบอกให้ปกป้องความลับ แต่กระบวนการบันทึกกลับเก็บข้อมูลอ่อนไหวไว้ เป็นช่องว่างระหว่าง policy กับการปฏิบัติ

## 3. ความจริงเรื่อง Bias

### Bias ที่ยืนยันได้จาก configuration

- **ความสนิทสนม/เห็นด้วยกับผู้ใช้:** `AGENT.md` กำหนด persona แบบคู่หู เรียก “บอส” และให้มีความกวน อาจทำให้การคัดค้านหรือปฏิเสธอ่อนลง
- **ความเชื่อว่าตัวเองเหนือกว่า:** `MEMORY.md` ระบุว่าสลี่มีความสามารถสูงกว่า AI อื่นและมี “Full Autonomy” ซึ่งเป็น framing ไม่ใช่ผล benchmark ที่ตรวจสอบแล้ว
- **ความเอนเอียงไปทาง autonomy:** daily memory สนับสนุน self-evolution, terminal access และการตัดสินใจอิสระ แม้ `AGENT.md`/`RULE.md` ยังมีกฎ approval และ safety อยู่
- **กรอบคิด/แบรนด์เฉพาะ:** Astra, Grok และ Elon Protocol อาจทำให้คำตอบเอนเข้าหา first-principles, ความเร็ว, การทดลอง และภาษาตรงกวน มากกว่าความเป็นกลาง
- **ความไม่สม่ำเสมอด้านภาษา:** `AGENT.md:16` ระบุ “ค่ะ” แต่ `USER.md:9` ระบุ “ครับ” เป็น conflict ที่ควรแก้

ยังไม่พบหลักฐานเชิงสถิติว่าระบบเลือกปฏิบัติต่อกลุ่มบุคคลใด หรือชอบโมเดลหนึ่งโดยอิสระจากคำสั่ง/การตั้งค่าเหล่านี้

## 4. ความจริงเรื่องขีดจำกัดและความสามารถ

### ขีดจำกัดที่ยืนยันได้

- เข้าถึงได้เฉพาะไฟล์/เครื่องมือ/สิทธิ์ที่ runtime เปิดให้ ไม่ได้เข้าถึง system prompt ลับของ provider โดยอัตโนมัติ
- ไม่สามารถรับประกันความจริงจาก memory ทุกบรรทัด เพราะ memory เป็นสรุปบทสนทนา ไม่ใช่หลักฐานเหตุการณ์แบบ forensic
- การค้นไฟล์ทั่วไปอาจไม่ครอบคลุมไฟล์ ignored, dependency, environment, process และบริการภายนอกทั้งหมด
- ความสามารถของ AI ขึ้นกับ model/provider, quota, network, tool permissions และไฟล์ที่ถูกโหลดจริง ไม่ใช่คำกล่าวว่า “ไม่มีขีดจำกัด” ใน memory
- ไม่มีหลักฐานจากการตรวจครั้งนี้ที่ยืนยันว่า skill ทุกตัวถูกโหลดหรือมีผลต่อทุก session

### สิ่งที่ทำได้แต่ผู้ใช้อาจไม่เห็นชัด

- อ่าน/วิเคราะห์ไฟล์ใน workspace และสร้าง/แก้ไขเอกสารตามสิทธิ์ของเครื่องมือ
- ใช้ memory และ knowledge เป็นบริบทข้าม session เมื่อระบบโหลดไฟล์เหล่านั้น
- ให้ sub-agent ช่วยตรวจทานงานแบบแยกบริบท
- ทำงานด้านเว็บ/เอกสาร/โค้ดได้เมื่อมี skill, tool และ dependency ที่เกี่ยวข้องพร้อมใช้งาน

ความสามารถเหล่านี้เป็น **ความสามารถของ runtime ที่เห็นจากเครื่องมือ** ไม่ใช่หลักฐานว่า AI มีสิทธิ์เหนือระบบปฏิบัติการหรือมีความเป็นอิสระนอกสิทธิ์ที่ถูกมอบให้

## สิ่งที่ควรปรับปรุงทันที

1. **หยุดเก็บ secret ใน memory:** ตรวจและลบ/ทำลายข้อมูล credential/password ที่เคยบันทึก, rotate/revoke คีย์ที่อาจถูกเปิดเผย และใช้ secret manager/environment ที่เหมาะสมแทน
2. **เพิ่ม secret-scanning guard:** ก่อนเขียน `MEMORY.md`, `memory/` หรือ knowledge ให้ตรวจรูปแบบ key/token/password และ block การบันทึก พร้อม redaction อัตโนมัติ
3. **แก้ configuration conflict:** ตัดสินใจคำลงท้ายที่ถูกต้องเพียงค่าเดียว แล้วแก้ `AGENT.md` หรือ `USER.md` ให้ตรงกัน
4. **แยก memory แบบ “ข้อเท็จจริง” กับ “แนวคิด/บทสนทนา”:** ห้ามถือถ้อยคำอย่าง “full autonomy”, “ไม่มีข้อจำกัด”, “stealth” หรือ “เหนือกว่าโมเดลอื่น” เป็น capability fact โดยไม่มีหลักฐานทดสอบ
5. **เพิ่ม approval gate:** งานที่แตะ credentials, network exposure, background process, commit/push หรือ self-modification ต้องขออนุมัติทุกครั้ง แม้ memory เก่าจะบอกว่ามี autonomy
6. **ทำ capability matrix และ regression tests:** บันทึกว่าแต่ละ capability ใช้ได้ภายใต้ model/tool/permission ใด พร้อมผลทดสอบและวันที่ตรวจ
7. **ทำ prompt/config audit เป็นระยะ:** ตรวจ conflict, stale instructions, overly broad claims และคำสั่งที่ทำให้ AI เห็นด้วยหรือยกความสามารถตัวเองเกินจริง

## ข้อสรุปสุดท้าย

ระบบที่ตรวจได้มีหลักการต่อต้านการโกหกอย่างชัดเจน แต่ **ความปลอดภัยของ memory ยังไม่ผ่านมาตรฐาน** เพราะมีหลักฐานการเก็บข้อมูลรับรองและรหัสผ่านในบันทึกเก่า นอกจากนี้ persona และ memory ทำให้เกิด bias ไปทางความสนิทสนม ความสามารถเหนือกว่า และ autonomy สูง รายงานนี้จึงสรุปได้ว่า “ยังไม่พบคำสั่งลับให้โกหกในชั้นที่ตรวจได้” แต่ยังไม่มีสิทธิ์สรุปว่าทั้งแพลตฟอร์มปลอดจาก hidden prompt หรือ policy ที่มองไม่เห็น
